## Rollout, compatibility, and rollback limits

The first migration adds the `WITHDRAWN` enum value. The second changes the reviewer-state constraint so `PENDING` and `WITHDRAWN` have no reviewer. These changes are additive to the stored request history; the rollout job applies them before the application revision.

The deployment workflow supports reusing a previously built image for a rollback and skips migrations in that mode. This does not reverse the database migration. Inference from the schema: an older Prisma client may not safely read rows whose state is `WITHDRAWN`; compatibility of an application rollback after any live withdrawal has been stored was not tested. Do not describe rollback as proven until that compatibility is checked.
